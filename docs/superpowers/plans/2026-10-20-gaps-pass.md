# Gaps Pass (v0.8.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the gaps found after the voice work: voice turns flagged as such, in-app problem reporting, edit/regenerate, side questions and background tasks, PDF attach, images in replies, server-side speech output, Opus uploads, a loud-room guard, a forwarding recogniser for Android 10/11, the two unanswered vault prompts, and JVM Compose UI tests.

**Architecture:** Each gap is one task on the existing seams: `GatewaySession`/`HermesApi` (wire), `ChatReducer`/`ChatState` (pure state), `ChatViewModel` + helpers (`ChatVoice`, `ChatAttachments`, `ChatMedia`), composables under `ui/chat` and `ui/voice`, platform adapters under `voice/` and `assist/`. New user-facing behaviour gets a pure, JVM-tested core and a thin Android shell, as before.

**Tech Stack:** As the repo (Kotlin 2.2, Compose BOM 2025.10, OkHttp 5, kotlinx.serialization, JUnit 4, Turbine, MockWebServer); Task 12 adds Robolectric 4.17 + `androidx.compose.ui:ui-test-junit4` (test only).

**Spec:** The user's answer to "what we missed" (2026-10-20): everything in that list except in-app updates (Obtainium) and localisation (deferred). Verified Hermes contracts in this plan's Global Constraints; app conventions in `docs/superpowers/plans/2026-10-20-tsukaima-android.md` and the rulings doc.

## Global Constraints

- Everything in the original plan's Global Constraints (tokens, copy rules, 44dp targets, motion, build/test commands, local Hermes only, commit trailer). **Never two Gradle builds at once.** One commit per task; `git add` explicit paths.
- Verified Hermes 0.22.2 contracts (live or from `~/.hermes/hermes-agent`):
  - `prompt.submit` params: `voice_turn: true` (the turn runs on the server's `auxiliary.voice_chat` model/persona), `interrupted: true` (client-side barge-in: the model gets an "interrupted" note), `truncate_before_row_id: <int>` + `confirm_truncate: true` (rewind: rows from that user row on are archived before the new turn; result carries `survivor_user_row_ids`/`survivor_row_id_map`), `confirm_deep_truncate: true` when the cut archives more than one user turn (send it always alongside). Result `user_row_id` is the persisted row of the accepted input. Transcript messages (`session.resume` / `session.history`) carry `row_id` (`TranscriptMessage.rowId` already parsed).
  - `prompt.btw {session_id, text}` / `prompt.background {session_id, text}` → `{task_id}`; results arrive as events `btw.complete` / `background.complete` `{task_id, text, question?}` on the parent session.
  - `pdf.attach {session_id, content_base64, filename, first_page?, last_page?}` → `{attached, filename, pages_attached, pages[{path,page,width,height}], count, text}` (pages are queued as images for the next turn; `text` is the server's note e.g. a page cap).
  - `POST /api/audio/transcribe` accepts `audio/ogg` (Opus) — verified: a 16 kB Opus upload transcribed verbatim where WAV was 276 kB. `POST /api/audio/speak {text}` → `{ok, data_url:"data:<mime>;base64,…", mime_type, provider}` (400 with `detail` on provider failure; the test instance's Edge TTS is broken, Piper is being installed for verification). `GET /api/audio/voice-config` → `tts: {mode, provider, …}` (never keep `api_key`).
  - Server requests `vault.save_login {origin, site}` → answer `{"value": "<JSON string {\"identifier\":…,\"password\":…}>"}` (`""` declines); `vault.code {site?, hint?}` → `{"value": "<code>"}` (`""` declines). Today the app answers both with `""` (declined) in `ServerRequestRouter`/`ConnectionManager`.
  - `android.media.MediaCodec` supports `audio/opus` encoding and `MediaMuxer.OutputFormat.MUXER_OUTPUT_OGG` from API 29 (minSdk).
- Copy for new strings: "Edit", "Regenerate", "Send as side question", "Send as background task", "Side question", "Background task", "Report a problem", "The app crashed last time", "Speech output", "On this phone", "On Hermes", "Too noisy to hear you — tap to retry", "Waiting for a code", "Waiting for a login", "Save login", "Enter the code".

## Review Focus

1. A rewind sent for a user row that history no longer holds (the session was compacted meanwhile): the server answers an error; the app must keep the composer text and show the error, never drop the transcript. Test: `ChatViewModelTest.editFallsBackWhenTheRowIsGone` (Task 3).
2. A `btw.complete` for a task the app never started (another client's): shown as a side note anyway, with its `question`; never crashes on a missing `question`. Test: `ChatReducerTest.sideNoteFromAnotherClient` (Task 4).
3. A PDF larger than the server's page cap: the chip shows the server's `text` note and the pages that did attach; the send still works. Test: `ChatAttachmentsTest.pdfPageCapNote` (Task 5).
4. An image URL that is not http(s) or that fails to load: the card shows the alt text and a broken-image glyph, no exception, no retry storm. Test: `MarkdownTest.imageBlockOnlyForHttpUrls` + `ChatMediaTest.imageLoadFailureIsCached` (Task 6).
5. `MediaCodec` Opus encoding fails on a device (no encoder, codec exception): the upload falls back to WAV in the same run, nothing is lost. Test: `OpusEncoderTest.fallbackOnFailure` via an injected encoder seam (Task 8).

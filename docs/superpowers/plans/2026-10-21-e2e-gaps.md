# E2E Gaps (v0.9.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the gaps the user found testing Tsukaima 0.8.x against their real Hermes 0.22.2: connector cards, todo checklists, three markdown gaps, vision images, queued sends, and honest interrupted-tool state.

**Architecture:** Every item is client-side against stock gateway contracts (verified in `~/.hermes/hermes-agent`, see Global Constraints). New server→client events become `ChatItem`s through `ChatReducer` (pure, tested); new RPCs go through `GatewaySession`/`HermesApi`; new markdown constructs extend the `MdBlock`/`MdSpan` model and `MarkdownText`. One release at the end.

**Tech Stack:** Kotlin, Jetpack Compose (BOM 2025.10.00), kotlinx.serialization, OkHttp, `ru.noties:jlatexmath-android:0.2.0` (LaTeX → Drawable, pure Java), JUnit 4 + Robolectric 4.17.

**Spec:** the user's test report `~/.claude/uploads/7f5c22e9-e6ca-4c09-b478-33d4ee25e148/e1fdb8a6-tsukaima-gaps.md` (copied to `docs/superpowers/2026-10-21-e2e-gaps-report.md` in Task 1), items 1–9. Items 1–2 blocking, 3–6 rendering, 7–8 behaviour, 9 keep.

## Global Constraints

- Everything in `docs/superpowers/plans/2026-10-20-gaps-pass.md` Global Constraints (tokens, copy rules, 44dp targets, local Hermes only, never two Gradle builds, one commit per task, explicit `git add`, lint baseline 19).
- Verified Hermes 0.22.2 contracts (source: `tui_gateway/contracts/connectors_operation.py`, `tui_gateway/methods_connectors.py`, `tui_gateway/tool_progress.py`, `tui_gateway/session_auto_continue.py`, `hermes_cli/web_routers/files.py`, `tools/file_operations_search.py`, `agent/replay_cleanup.py`):
  - Event `connection.request` `{op_id, seq, deadline_at (epoch s), timeout_seconds, targets[{name, kind, action, state, resolved?, detail?, instructions?, connect_url?, required_env?[{name, required, secret, default, prompt?}], hint?, display?, description?}], tool_call_id?, display?{suggested[]}}`. Progress: event `connection.update` `{op_id, seq, deadline_at, settled, settled_by?, targets[], owner, target?, from?, to?, actor?, detail?}` (also broadcast globally). RPC `connection.respond` params = `{owner: {type: "session", session_id: <sid>}, op_id, result: {targets[{name, status: "approved"|"skipped", detail?, env?{k:v}}], settled_by?: "continue"}}` (`ConnectionOperationParams` requires `owner`; the desktop builds it from the session id — `apps/desktop/src/store/connection-request.ts:494`) → `{status:"ok", settled}`; invalid answer → 4002. RPC `connectors.operation.wake {owner, op_id}` → `{status:"ok"}` after a browser leg. Unanswered requests hang the tool until `deadline_at` (~5 min).
  - Event `todo.updated` `{todos[{id, content, status: pending|in_progress|completed|cancelled, parent?}], revision}` (full snapshot, monotonic `revision`, fires regardless of tool-progress settings); the same `todos`+`revision` are mirrored on the todo tool's `tool.complete`; `summary` exists only in `tool.complete.result.summary`.
  - `GET /api/media?path=<abs or ~ path>` → `{"data_url": "data:image/<type>;base64,…"}`; 403 outside `~/.hermes/{images,screenshots,cache}`, 404 missing, 413 over 25 MiB, 415 non-image suffix (png/jpg/jpeg/gif/webp/svg/bmp/ico). `vision_analyze` args carry `image_url` (http(s) or a local path).
  - `prompt.submit` while the session runs: `{…, "queued": true}` → `{status:"queued"}`; the message is persisted at accept and runs after the live turn (`_drain_queued_prompt`). Without `queued` the server applies `display.busy_input_mode` (default `interrupt` = redirect/kill the live turn) — the app must always send `queued: true` mid-turn. A truncation mid-turn is 4009 (unchanged).
  - Interrupted terminal tool: `tool.complete.result = {output: "<partial>\n[Command interrupted]", exit_code: 130, error: null}`. History may carry orphan-recovery notices: `[Orphan recovery: interrupted side-effecting tool may have executed; its effect is UNKNOWN. Inspect state before retrying.]`, `[Orphan recovery: interrupted read-only tool did not complete.]`, `[Orphan recovery: this tool may have executed before Hermes stopped; …]`, `[Orphan recovery: this read-only tool did not complete and had no effect.]`. Turn-end reasons (`interrupted_by_user`, `interrupted_during_api_call`) are **not** on the wire.
  - Tool failure predicate (keep): failed ⇔ `result.error` truthy **or** `result.success == false` **or** `result.exit_code != 0`; an interrupted tool is a distinct state, not a failure.
- Copy for new strings: "Connect", "Skip", "Skip all", "Continue", "Hermes wants to connect", "Waiting for a connection", "Tasks", "Queued", "Send when done", "Interrupted", "May have partially run — check before retrying", "Did not complete".
- LaTeX renders through `ru.noties:jlatexmath-android:0.2.0`; a formula that fails to parse renders as inline code with the raw TeX (never crashes). Math is never spoken (`SpeechText` drops it).

## Review Focus

1. A `connection.request` that arrives while the app is backgrounded: the notification path must raise "Hermes needs your attention" and the card must still be answerable after reopen (`session.resume` replays open requests) — Task 1 test `connectionRequestSurvivesResume`.
2. Two `todo.updated` events arriving out of order (revision 3 then 2): the card must keep revision 3 — Task 2 test `staleTodoRevisionIsIgnored`.
3. A `$` in prose that is money ("$5 and $10") must not become math — Task 3 test `dollarAmountsAreNotMath`.
4. A queued send when the live turn ends before the RPC lands (server answers `{status:"streaming"}` instead of `queued`): the bubble must become a normal sent message, not stay "Queued" — Task 5 test `queuedSendThatRunsAtOnceIsNotMarkedQueued`.
5. A `vision_analyze` with a path outside the media roots (403): the tool row shows the normal result and a small "image unavailable" note, never an error state — Task 4 test `mediaForbiddenLeavesTheToolRowIntact`.
